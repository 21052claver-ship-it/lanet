## Com interpretar els documents

- **Estat vigent:** decisions actuals i pendents; es contrasta amb el registre i els rebuts.
- **Informe de versió:** fotografia d’una publicació concreta. La release/tag i el rebut original són immutables.
- **Plans datats:** expliquen abast, decisions i evidències d’una revisió; poden contenir opcions després substituïdes.
- **Històric i mockups:** es conserven per traçabilitat, sense convertir-los en instruccions noves. El xat/Dubtes està retirat a la 0.6.16.

Les instruccions humanes posteriors prevalen. Els controls de treball són els d’AGENTS.md i CONTRIBUTING.md; SEGUIMENT.json és la font dels estats i CHECKLIST.md és una vista generada, no una segona llista editable.

## Actualitzar la documentació

1. Obrir una única tasca al registre abans de començar i definir què es modifica.
2. Actualitzar l’estat o informe corresponent; conservar els registres antics i marcar decisions substituïdes.
3. Afegir l’entrada d’historial i evidències sense secrets ni dades reals d’usuaris.
4. Regenerar la checklist amb `npm run plan:sync` i comprovar-la amb `npm run plan:check` al workspace que conserva les evidències privades.
5. Validar enllaços locals, coherència de les xifres, format i auditoria de font abans d’un futur push. El flux branca/PR continua sent obligatori per incorporar canvis a main.

Els canvis només documentals no necessiten una nova versió de producte ni tornar a desplegar. Aquesta ordenació queda desada localment per incorporar-la a una pròxima tanda; no genera una publicació duplicada.
